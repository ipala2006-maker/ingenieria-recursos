# estudiemos.ar: assets and HTTPS

The app is a static HTML/CSS/JavaScript PWA, not Next.js. There is no `_next/static`
directory to rewrite. `wrangler.frontdoor.jsonc` binds the exact custom domain to
`estudiemos`, and `ASSETS` serves `dist-cloudflare`. Existing relative resource URLs
correctly resolve on estudiemos.ar, including version query strings and local fonts.
Never return the app HTML as a fallback for a missing stylesheet or script.

## HTTPS policy

The DNS delegation now uses leif/luciane and the Cloudflare zone is active. Its free
Universal SSL certificate is active. `Always Use HTTPS` is enabled on the zone:
HTTP requests, including static assets, redirect before reaching the application.
Keep this setting on; an HTTP page combined with secure-resource/CSP restrictions
can display as unstyled HTML even when the HTTPS assets themselves are healthy.
Do not disable CSP, `nosniff`, HSTS or certificate validation to mask this symptom.

`cloudflare/frontdoor.mjs` also upgrades direct HTTP requests for estudiemos.ar to
HTTPS with a 308 before forwarding to bindings. It preserves the path/query and
never redirects arbitrary hosts. Static CDN requests still bypass Worker execution;
do not replace `assets.run_worker_first` with `true` merely to implement redirects.
The zone setting is necessary for those asset-first requests.

No cross-origin proxy, paid certificate, new Worker, database change or secret is
required. Existing workers.dev clients and backend callbacks remain intact. This
repair is not a silent migration of OAuth/Auth/native origins or installed sessions.

## Ads

`/ads.txt` is a real text asset, not a rewrite. The existing AdSense adapter remains
asynchronous, bottom-only/non-expanding, Free/consent gated, and absent for active
Pro/No Ads or the unsupported native Android WebView. No real ad impressions are
generated by tests. Approval and the actual consent-manager bridge remain separate
activation prerequisites; successful loading of the app is not AdSense approval.

## Verification and deployment

```powershell
node --test tests/cloudflare-frontdoor.test.js tests/public-origin.test.js tests/ads.test.js
node scripts/csp-check.js
node scripts/build-cloudflare.cjs
npx --no-install wrangler deploy --config wrangler.frontdoor.jsonc
node scripts/verify-public-origin.cjs
```

The public check validates TLS using Node's default certificate validation, HTTP
redirect targets, all three app pages, representative CSS/JS/fonts/icons, the PWA
manifest/service worker, HSTS and the exact publisher in ads.txt. It sends no account
credentials and prints no private API response or task content. Also check the live
browser for stylesheet/font loading, runtime errors and mobile overflow.

Zone setting reference:
https://developers.cloudflare.com/ssl/edge-certificates/additional-options/always-use-https/
